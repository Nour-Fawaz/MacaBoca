\section{Critical Assumptions}

\wss{These assumptions that are made about the software or system.  You should
minimize the number of assumptions that remove potential hazards.  For instance,
you could assume a part will never fail, but it is generally better to include
this potential failure mode.}

\begin{itemize}
    \item Assume that the clinicians using the system are licensed speech-language pathologists.
    \begin{itemize}
        \item This assumption is made since the system is designed to support clinical assessment. If the clinician is not licensed, then they should not be assessing or diagnosing a child's speech and language abilities.
    \end{itemize}
    \item Assume that the clinicians have access to an approved device with stable internet.
    \begin{itemize}
        \item This assumption is made since the system is designed to be used on a desktop or laptop with a web browser. If the clinician doesn't have access to such a device or stable internet connection, they would not be able to use the system.
    \end{itemize}
    \item Assume that clinicians review the system's flags and transcripts before relying on them, so that they're making the final judgement.
    \begin{itemize}
        \item This assumption is made since the system is designed to assist clinicians, not replace them. If clinicians rely on automatically generated results without reviewing them, then errors in transcription or flagging may lead to incorrect conclusions about a child.
    \end{itemize}
    \item Assume that patients and caregivers have consented to the assessment being recorded and stored.
    \begin{itemize}
        \item This assumption is made since the system records and stores video of children. If consent has not been given, then the recording should not be collected or stored by the system, nor should any assessment be conducted via the system.
    \end{itemize}
    \item Assume that the assessment contents are provided by a professional research team and are clinically correct.
    \begin{itemize}
        \item This assumption is made since the system is designed to support real, professional clinical assessments and the team isn't responsible for designing the assessments themselves. If the assessment content is incorrect, then the results shown to clinicians may be misleading even if the system works as intended.
    \end{itemize}
    \item Assume that assessments are conducted in languages supported by the transcription model.
    \begin{itemize}
        \item This assumption is made since the system relies on an existing speech recognition model. If an assessment is conducted in an unsupported language, then the system will not be able to generate a meaningful transcript.
    \end{itemize}
    \item Assume that the clinician has instructed a patient with speech or language difficulties to use this system, and that the patient is able to use the system without any assistance.
    \begin{itemize}
        \item This assumption is made since the system is designed to be used by patients with speech or language difficulties. If the patient is not able to use the system without lots of assistance from an external body, then the assessment may not be completed accurately.
    \end{itemize}
\end{itemize}

\subsection{Catherine}
\subsubsection*{Question 1}
As a team, hazards and risks had already been heavily discussed throughout the project, so
during meetings, we were able to easily brainstorm and discuss each section of the deliverable,
and divvy up all the parts. As we now had quite a bit more resources, it was also easier to
ask more guided questions when we were confused or not aligned with one another on a concept
related to our project, so communication was also a lot more clear for this deliverable. 
Pre-splitting the system into components also made it easy 
to divide the work between us, since each person could focus on the parts they were most
familiar with.

\subsection{Team}
\subsubsection*{Question 3}
Before starting this deliverable, we had already thought about and discussed in pretty
deep detail different risks and hazards to consider, especially for a project that touches
real patients and health practices. For instance, as mentioned throughout the deliverable,
because the system stores video recordings and health records of children, privacy and 
data security were something we talked about extensively from the start. They also 
come up in our previous deliverables. We also knew that the transcription model could
have trouble differentiating between speakers, different languages, or sentences in general,
so we also knew that a clinician would always have to be within the loop and ensure that
everything has been reviewed and verified by a licensed clinician.

Other risks only came up while doing the Hazard Analysis, where going through each component
made us think about how each part could fail on its own, instead of just the system as a
whole. For example, while writing about the database and report generation module, 
we realized a clinician could potentially view or edit the wrong patient assessment, or
lose important edits without knowing, resulting in incorrect results. 
Writing the critical assumptions also brought up risks we hadn't considered, like what happens 
if the internet cuts out partway through an assessment, or
if the child happens to need a lot of help from a parent during their assessment and the parent
happens to interfere too much. Trying to decide whether these should be assumptions or actual 
hazards made us think more about what we could realistically control, and if so then how.
